# Architectural Design Goals

**DG-01 Security (Priority: High) -** Customer personal data and restricted actions are available only to authenticated staff with authorised role. The server checks every request before data is read or changed, and denied attempts are logged. This goal comes from NFR-02, NFR-07 and NFR-12, and it supports FR-09 and FR-13. The CRM holds contact details, dates of birth, travel history and complaint notes. Loyalty points also have monetary value, so a missed permission check on an adjustment over 3,000 points (UC-09) would cost the airline money.

**DG-02 Maintainability (Priority: High) -** Each part of the system can be changed or replaced without rewriting the others. The UI, the business rules and the database are kept apart, and the business rules are split by the three already defined scopes. This goal comes from NFR-15 and from the scope split of FR-01 to FR-15. NFR-15 also requires moving from local PostgreSQL to Neon by changing only connection settings, which works only if all database code sits in one place.

**DG-03 Performance (Priority: Medium) -** Frequent lookups should answer quickly enough for a CSR on a live call. Customer search should return within 2 seconds, the satisfaction trend view within 3 seconds and the dashboard within 5 seconds. This goal comes from NFR-01, NFR-06 and NFR-11. UC-01 Locate Customer is included by UC-03, UC-05, UC-06 and UC-09, so a search runs at the start of almost every interaction. It is Medium priority because the data sizes are modest (5,000 customers for search). We accept a small cost from layering in return for DG-01 and DG-02.
